# Как устроена система (для руководителя)

## Из чего состоит

Система состоит из двух частей:

- **Сайт**: то, что видит пользователь в браузере. Это экраны, кнопки и формы.
- **База данных**: хранилище, где лежат объекты, задачи, пользователи и история. Мы используем облачный сервис Supabase.

Главное: **все правила проверяет база данных, а не сайт.** Сайт только показывает нужные кнопки.
Даже если кто-то обойдёт сайт и отправит запрос напрямую (например, исполнитель, разбирающийся в программировании),
база проверит, кто он, и откажет, если действие ему не положено.

## Кто что может

**Постановщик** (руководитель, прораб):
- создаёт, редактирует и удаляет объекты и задачи;
- назначает исполнителя;
- принимает выполненную задачу или возвращает её на доработку. При возврате комментарий обязателен: исполнитель увидит, что исправить;
- видит всё.

**Исполнитель**:
- видит только свои задачи и только те объекты, где у него есть задачи;
- берёт задачу в работу и отправляет её на проверку.

## Путь задачи

```
Новая → В работе → На проверке → Принята
                        ↓
                   На доработке → В работе → ...
```

Каждый шаг записывается в **историю**: кто, когда, из какого статуса в какой и с каким комментарием.
Историю видят обе роли в карточке задачи.

## Чего исполнитель сделать НЕ может, даже в обход сайта

- Увидеть чужие задачи, объекты без своих задач и коллег-исполнителей.
- Изменить название, описание, объект или исполнителя задачи, даже своей.
- Создать или удалить задачу или объект.
- Сам принять свою задачу или перескочить шаг, например из «Новой» сразу в «Принята».
- Двигать чужую задачу.
- Повысить себе права до постановщика.
- Добавить, исправить или удалить запись в истории.

**Постановщик тоже не может подделать историю.** Записи в неё делает только сама база при смене статуса.
Поэтому журнал можно использовать при разборе спорных ситуаций.

## Как это проверено

Есть автоматическая проверка из 36 попыток «взлома»: вход под разными пользователями и попытки сделать запрещённое
напрямую через базу, минуя сайт. Все 36 попыток база отклоняет.

## Остальная защита

- **Регистрация закрыта.** Посторонний не может завести себе аккаунт. Пользователей добавляет администратор.
- **Секретные ключи не попадают на сайт.** На сайте есть только публичный ключ. Он сам по себе ничего не открывает:
  без входа по логину и паролю база не отдаёт никаких данных.
- Роль пользователя хранится в базе. Сам пользователь изменить её не может.
